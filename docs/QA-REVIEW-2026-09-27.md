# QA review — September 27, 2026

This review covers the `0.6.0` candidate as a Blender extension. It checks the
non-destructive scope and documented interaction contract in [DESIGN.md](DESIGN.md),
the build and test workflow in [CONTRIBUTING.md](../CONTRIBUTING.md), the actual
installed sidebar, and the open 1.0 gate tickets. It is a test record for this
revision, not a claim that the 1.0 release gate is complete.

## Environment and results

Official Blender 5.1.2 and 5.2.2 Linux archives were downloaded from Blender's
release server and verified against its SHA-256 files. Both were run outside the
restricted process sandbox because that sandbox prevents Blender's audio event loop
from exiting cleanly. The system package was 5.0.1, below the declared 5.1 minimum.

| Check | Blender 5.1.2 | Blender 5.2.2 |
| --- | --- | --- |
| `scripts/validate.sh` | Pass: 363 tests across 11 suites | Pass: 363 tests across 11 suites |
| EEVEE and Cycles output smoke | Pass | Pass |
| Extension manifest, build, archive validation | Pass | Pass |
| 100-annotation SVG drawing-sheet export | 0.095 s | 0.124 s |
| 200-line spacing draw preparation / snap query | 0.136 / 2.347 ms | 0.169 / 2.510 ms |

The suite exercises anchors and repair, modal placement, saved-file migrations,
scene and library lifecycle, renderable Grease Pencil output, SVG/PDF geometry,
dimension sets, circular dimensions, and packaging. The final ZIP was also installed
in an isolated Blender 5.2 profile; enable, disable, and re-enable all succeeded.

On Blender 5.2.2, the standalone draw benchmark measured 0.508 ms per rebuilding
frame for 10 dimensions, 0.501 ms with 10,000 unrelated objects, and 27.590 ms for
500 dimensions (36 fps worst-case CPU preparation). The 500-dimension result meets
the documented 30 fps budget. The one-million-vertex snap benchmark measured a
57.210 ms cold build, 0.130 ms reprojection, and 0.019 ms steady query, within the
documented 100 ms / 50 ms / 8 ms budgets. These Linux numbers are separate from the
Windows reference table in [DESIGN.md](DESIGN.md#measured-performance).

## Installed UI and interaction

The built ZIP was installed and enabled in an isolated Blender 5.2.2 profile. On a
1600 × 900 virtual display at Blender's default narrow sidebar width, the Dimensions
tab drew without errors. A dimension was created from two snapped cube vertices;
the live preview showed **2.828 m**, the saved annotation appeared in the viewport
and Annotation Manager, and the manager's Hide and Show controls removed and
restored its overlay. No mesh geometry was altered.

The review found that the three construction buttons truncated their names and
manager rows left only a few characters for annotation names. The revised sidebar
uses two construction rows and moves selected-item value, state, and actions below
the manager list. The installed ZIP was rebuilt and visually checked with a long
annotation name and the Hide/Show workflow.

The sidebar is still dense at its default width. Eleven icon-only Snap Targets
require hover tooltips, and the lower management/output panels require scrolling.
These are usability improvements for a later focused UX pass; no incorrect action
was observed in the tested workflow. Foreground UI interaction was checked on 5.2.2
only; 5.1.2 was covered by the full background suite.

## Correctness changes and remaining gate

This review also closed the `FND-12` supported-version validation gate. A focused
`FND-13` slice now refuses Chain member reordering that could reverse a segment,
removes the Annotation Manager entry when the final set member is deleted, restores
annotation visibility properties even when the collection is excluded from a view
layer, and omits the deprecated Grease Pencil `show_stroke` write. Targeted
regressions and both full Blender validation runs pass.

The 1.0 gate remains open. [FND-13](tickets/FND-13-lifecycle-modal-cleanup.md) still
tracks older-schema scenes with settings but no annotation objects, linked-data
migration boundaries, and modal preview ownership/cleanup. [OUT-06](tickets/OUT-06-vector-typography-page-bounds.md)
still tracks printable annotation bounds, title-block field fit, and vector glyph
and alignment correctness. These are documented correctness gaps, so this review
does not recommend labeling the candidate 1.0 ready.
